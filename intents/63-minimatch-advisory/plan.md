## Risks

- **An override past the declared range.** typescript-estree declares
  `minimatch ^10.2.2`, and 11 is a major version. Possible breakage:
  - a removed or renamed export;
  - an ESM/CJS change in how it loads;

  Each is checked under "Verified against the codebase". The proof is lint's
  output, before and after, location by location. A count that merely stays
  the same is not enough.
- **An override that's too wide.** A global `"minimatch": "…"` would also move
  eslint's own `minimatch@3.1.5`, a different API used by
  `@eslint/config-array` and `@eslint/eslintrc`. That could change which files
  eslint lints. The override must be **scoped** to typescript-estree, and
  eslint's copy must stay at 3.1.5 (an intent constraint).
- **A lockfile that only works on this machine.** A clean `npm ci` must work
  from the committed lockfile in a fresh checkout.
- **The lint cap.** The cap stays at 21 and is never raised. A rise in
  warnings means the override changed behaviour, so stop.
- **An unproven claim.** There is no unit test, by the intent's constraint
  ("No `src/`, `server/` or test change"). The evidence is command output
  recorded in Progress, before and after, so the record must quote it exactly

- **Stale numbers.** The audit, versions and dates below are as of
